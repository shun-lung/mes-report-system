# 03 測試案例（第 3 階段）

## 這份文件在做什麼

測試案例＝「**照著做就能判斷對錯**」的步驟。每個案例有：前置條件、步驟、預期結果。
寫得好的案例，換任何人來做結果都一樣。

## 設計技巧（用報工系統舉例）

### 1. 等價分割：把輸入分成幾組，每組挑一個代表

報工數量分三組，每組行為一樣，所以每組測一個就好，不用 0～1000 全測：

| 組 | 例子 | 預期 |
|---|---|---|
| 無效：0 | 報 0 雙 | 擋下（TC-17） |
| 有效：1～可報量 | 報 60 雙 | 成功（TC-20） |
| 無效：超過可報量 | 報 101 雙 | 擋下（TC-18） |

### 2. 邊界值：Bug 最常出現在「剛好」的地方

`<` 寫成 `<=` 這種錯，只有測邊界才抓得到：

| 情況 | 測 | 預期 |
|---|---|---|
| 可報 100 雙 | 101 / 100 | 擋下 / 成功（TC-18） |
| 製令 100 雙 | 末站報到 99 / 100 | 生產中 / 完工（TC-23） |
| 成型站 100 雙 | 報到 99 / 100 | 繼續上工 / 自動下工（TC-14） |
| 250 雙開卡 | 最後一張 | 50 雙（TC-01） |

### 3. 狀態轉換：哪些「狀態 → 狀態」允許、哪些不允許

```
草稿 ──開立──▶ 已開立 ──報工──▶ 生產中 ──報滿──▶ 完工
  │              │                 │                │
 修改✓          取消✓             結案✓            結案✓、入庫✓
                結案？(BUG-001)    取消✗、入庫✗
```
