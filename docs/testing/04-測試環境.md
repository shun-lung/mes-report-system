# 04 測試環境（第 4 階段）

## 為什麼要另開測試資料庫

測試會一直新增、刪除資料。如果用開發中的 `mes` 資料庫，你手動建的訂單會被清掉。
所以另開 `mes_test`，**每個測試開始前都清空重建**，測試要怎麼弄亂都沒關係。

程式裡有保護：資料庫名稱不含 `test` 就拒絕執行，避免誤清正式資料。

## 測試用的最小工廠

由 `backend/internal/testutil/testutil.go` 自動建立：

| 項目 | 內容 |
|---|---|
| 站點／線別 | 成型（A、B 線）→ 整理（A 線） |
| 成品 | T-FG 測試拖鞋，每卡 100 雙 |
| 用料 | 大底（到站扣帳，成型用 1 雙）、鞋盒（倉庫發料，整理用 1 個） |
| 倉庫 | 原物料、成型暫存、成品、完工暫存 |
| 期初庫存 | 大底 1000、鞋盒 1000 |
| 時間 | 固定 2026-11-10 10:00（早班） |

## 怎麼執行

### 第一次（建立 mes_test，只要做一次）

```bash
cd 報工系統
docker compose -f deploy/docker-compose.yml start
docker compose -f deploy/docker-compose.yml exec -T db psql -U mes -d postgres -c "CREATE DATABASE mes_test"
```

### 每次執行測試

```bash
cd 報工系統/backend
export TEST_DATABASE_URL='postgres://mes:<本機密碼>@localhost:5433/mes_test?sslmode=disable'
go test -p 1 -count=1 -v ./internal/production/
```

- `-v`：列出每個案例的結果（PASS 通過、FAIL 失敗、SKIP 略過）。
- `-p 1`：一次只跑一個套件，避免多個套件同時清同一個資料庫。
- `-count=1`：不用上次的快取結果，一定重跑。
- 沒設 `TEST_DATABASE_URL` 時，整合測試會自動略過（SKIP）。

### 只跑某一個案例

```bash
go test -p 1 -count=1 -v -run TestTC31 ./internal/production/
```

## 自動執行（GitHub Actions）

`.github/workflows/test.yml`：每次 push 到 GitHub，雲端會自動開一台機器、裝 PostgreSQL、跑全部測試和前端型別檢查。
結果在 GitHub 專案的「Actions」頁籤：綠勾＝全部通過，紅叉＝有測試失敗，點進去可以看到是哪一個。

目前 Render 部署不受測試結果影響（push 就部署）。之後可以改成「測試通過才部署」。
