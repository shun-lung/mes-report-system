## 4. 測試真的有效嗎？（變異檢查）

測試全部通過，也可能是因為測試根本沒在檢查。所以我**故意把一條規則改壞**：拿掉「未完工不能入庫」的檢查。
結果 TC-30 立刻失敗（「預期失敗（尚未完工），實際卻成功」），證明這個測試真的守得住這條規則。檢查完已把程式改回來。

## 5. 沒測到的風險

- 採購、缺料預警公式、Excel 匯入、權限、拆卡合併：本輪範圍外。
- 跨班、跨午夜的生產日：測試時間固定在早班。
- 多站（4 站）、多線同時上工：測試工廠只有 2 站 3 線。
- 畫面顯示：只有手動案例，而且還沒執行。
- 同時兩個人操作同一張製令（並發）：沒有測。

## 6. 結論與建議

- 主流程的高優先規則全部通過，帳務、庫存、工時沒有發現錯誤。
- **建議 1**：決定 BUG-001 要不要修（修法很小：結案只允許生產中、已完工）。

- **建議 3**：之後每次改程式都會由 GitHub 自動重跑這 35 個測試（回歸測試）；可以考慮改成「測試通過才部署到雲端」。
